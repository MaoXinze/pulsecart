# PulseCart 需求分析说明书

## 1. 文档目的与范围

本文把 PulseCart 的产品目标转换为可实现、可验收的需求。需求范围覆盖数据导入、人工审核、模型训练编排、问题卡管理、权限审计和本地部署。

一期重点是“数据可信和问题可闭环”，而不是堆叠模型数量。所有功能分为四种状态：

- **已实现并验证**：当前代码和本地流程已经验证；
- **已实现但有条件**：代码具备，但依赖服务、数据量或环境尚未完整满足；
- **规划中**：本文定义目标，当前不能作为交付事实；
- **历史资产**：旧项目中的实验能力，暂不进入默认线上路径。

| 角色 | 数据集 | 人工审核 | 训练评测 | 问题卡 | 系统管理 |
| --- | --- | --- | --- | --- | --- |
| 商品运营 | 查看、导入 | 编辑、提交 | 查看 | 创建、分派、验证 | 无 |
| 品类负责人 | 查看、导入 | 查看、抽查 | 查看 | 查看、分派、关闭 | 无 |
| 客服/售后负责人 | 查看 | 审核 | 查看 | 创建、跟进、验证 | 无 |
| 数据分析师 | 查看、导入、导出 | 审核、复核 | 创建、查看 | 查看 | 无 |
| 算法工程师 | 查看脱敏数据 | 查看质量结果 | 创建、评测、发布 | 查看 | 模型配置 |

当前 JeecgBoot 登录体系以 `admin` 演示账号为主，领域接口要求已认证用户。更细的角色和数据范围控制属于 P4/P5，需要在不破坏系统表权限的前提下补充领域权限。

## 3. 功能需求

### 3.1 数据集导入

**目标**：将不同来源的评论文件转换为统一、可追溯的数据集版本。

**输入契约**：

- 必填字段：`review_id`、`product_id`、`review_text`、`reviewed_at`；
- 推荐字段：`category_id`、`channel`、`rating`、`product_version`；
- 当前一期只接受 UTF-8 CSV；
- 支持标准字段、常见别名和显式字段映射；
- 文件大小受后端上传配置限制。

**校验规则**：

1. 文件扩展名必须为 `.csv`，文件不能为空；
2. 必填列缺失时拒绝导入；
3. `review_id` 在同一数据集内必须唯一；
4. 评论文本不能为空，长度必须在配置范围内；
5. 日期必须能解析为 ISO 日期/时间；
6. 评分如果存在，必须为 1 到 5 的整数；
7. 识别并记录字符级语言标记；
8. 多余列给出质量提示，不得静默丢失；
9. 同一文件字节内容和同一映射重复提交时幂等复用版本。

**输出**：`dataset_version`、文件 SHA-256、映射、质量规则、接收行数、有效行数、拒绝行数、拒绝原因、规范化评论。

**验收**：给定演示 CSV，系统生成 `ds-9b8a078d8df7010a`，报告和记录可以在本地文件与 MySQL 中互相核对；错误行可通过拒绝报告解释。

### 3.2 演示数据初始化

管理员可以初始化固定的扫地机器人合成数据：约 1,200 条评论和约 300 条审核任务。初始化必须幂等，不得重复创建同一 `task_id` 或数据集版本。

合成数据只能用于功能演示、测试和流程联调。它不能证明模型对真实用户评论的泛化效果。

### 3.3 人工审核

审核任务至少包含：评论 ID、来源数据集、抽样组、抽样原因、系统预测、系统置信度、人工情感、人工属性、审核说明、审核人和审核时间。

审核状态：

```text
pending -> approved
pending -> verified
pending -> rejected
approved -> verified
approved/verified -> rejected（发现文本无效时）
```

规则：

- `approved` 或 `verified` 必须填写 `positive`、`neutral` 或 `negative`；
- `rejected` 必须填写原因；
- 不允许修改原始评论文本；
- 人工属性使用受控字符串列表，不能用自由文本污染统计口径；
- 审核结果用于训练前，必须保留原任务和数据集版本。

### 3.4 训练与评测运行

创建训练运行时必须传入：`dataset_version`、`model_version`、`source_kind=human_reviewed`。

系统只选取同一数据集版本中状态为 `approved` 或 `verified` 且具备人工情感标签的任务。`synthetic_reference` 不得直接进入训练记录。

训练运行至少保存：

- 运行 ID和训练任务 ID；
- 数据集版本、模型版本、随机种子；
- 人工审核样本数、训练样本数、测试样本数；
- Accuracy、Macro-F1、分类报告和混淆矩阵；
- 开始时间、结束时间、失败原因和发布状态。

当前最低创建条件为 15 条人工审核样本；发布条件为 Macro-F1 至少 0.65 且独立测试样本至少 30 条。低于发布条件的运行可以用于 `evaluation_only`，不能作为默认生产模型。

### 3.5 商品体验问题卡

问题卡至少包括：数据集版本、标题、体验属性、严重度、状态、描述、来源评论 ID、负责人、处理说明、创建人和更新时间。

严重度：`low`、`medium`、`high`、`critical`。

状态机：

```text
open -> in_progress
in_progress -> open
in_progress -> pending_validation
pending_validation -> in_progress
pending_validation -> closed
closed -> 终态，不允许继续流转
```

关闭要求：必须先进入 `pending_validation`，并填写验证结论。来源评论必须属于问题卡声明的数据集版本。

### 3.6 查询、导出和证据

分析结果必须支持按数据集、商品、类目、渠道、产品版本、时间窗口和属性筛选。每个聚合结果应返回数据集版本、模型版本、筛选条件和生成时间。

当前 P1 已实现数据集、审核任务、训练运行和问题卡接口；趋势聚合、属性排行、导出和告警属于 P2/P3 需求。

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 可追溯性 | 文件、数据集、审核任务、训练运行和问题卡之间可通过版本/ID关联 |
| 幂等性 | 重复导入、演示初始化、任务查询不产生重复业务数据 |
| 安全性 | 不保存真实身份信息；上传文件限制大小；接口必须鉴权；密钥不提交 Git |
| 一致性 | 状态流转由后端校验，前端不能绕过状态机 |
| 可恢复性 | 训练失败保留失败状态和错误信息；原始文件与规范化记录分离保存 |
| 可观测性 | 记录请求、任务、耗时、依赖失败和版本信息 |
| 可测试性 | 导入、标签隔离、状态机、训练编排和发布门槛可自动化验证 |
| 可扩展性 | NLP 服务与业务 API 独立；未来可以替换基线模型或接入异步 worker |

## 5. 异常与降级需求

### 5.1 数据异常

- CSV 解析失败：返回明确错误，不创建数据集；
- 必填列缺失：返回缺失字段列表；
- 部分行错误：有效行进入版本，拒绝行写入报告；
- 重复文件：返回已有版本，并标记 `reused=true`；
- 超限文件：在读取后端业务处理前拒绝，避免无限制占用内存。

### 5.2 NLP 服务异常

- NLP 服务不可达：不创建伪造的成功训练结果，返回依赖错误；
- 训练服务返回非法 JSON 或未知状态：任务标记为同步失败，保留错误信息；
- 训练过程中失败：分析运行进入 `failed`，可以重建新运行，不能篡改旧运行；
- 指标低于门槛：保留评测结果，但模型状态必须是 `evaluation_only`。

### 5.3 数据库和缓存异常

- MySQL 不可用：读写领域数据应明确失败；不能向前端返回伪造的空成功结果；
- Redis 不可用：P1 同步路径可以继续；P4 异步任务需要进入重试或失败队列；
- 对象存储不可用：只允许在本地开发模式使用版本目录，部署模式必须阻止丢失原始文件。

## 6. 数据需求

### 6.1 数据分层

| 数据层 | 内容 | 生命周期与权限 |
| --- | --- | --- |
| demo | 合成评论和固定审核任务 | 可进入仓库，声明来源和用途 |
| raw | 原始客户或公开下载文件 | 本地/对象存储，禁止提交 Git |
| normalized | 规范化评论和拒绝报告 | 按数据集版本只读保存 |
| reviewed | 人工审核结论 | 可用于训练和评测，保留审计 |
| model | 模型文件、指标和发布记录 | 版本化，支持回滚 |
| issue | 问题卡与处理记录 | 业务团队可见，关闭后保留 |

### 6.2 数据保留原则

- 原始评论和规范化记录不能覆盖更新；
- 修正标签新增审核记录或更新带审计字段的任务，不修改原评论；
- 脱敏前不得进入演示目录；
- 导出文件应包含数据集版本和生成时间；
- 删除真实数据必须通过明确的数据保留策略和管理员审批，一期不提供物理删除接口。

## 7. 验收标准

### P1 必须通过

1. 演示 CSV 可以导入并生成稳定版本；
2. 缺失列、空文本、重复 ID、非法日期和非法评分均有可解释结果；
3. 重复导入返回 `reused=true`，不重复插入评论；
4. 演示审核任务可以查询并保存三类人工标签；
5. 训练请求只包含 `approved`/`verified` 样本；
6. 训练状态可以从 NLP 服务同步回业务库；
7. 低样本和低指标模型不能被标记为可发布；
8. 问题卡不能跳过验证阶段直接关闭；
9. 数据库表和本地运行步骤可按部署文档复现。

### P2/P3 通过条件

- 看板聚合与明细证据的数量可以相互核对；
- 同一 SKU 的时间窗口比较使用固定数据和模型版本；
- 导出结果可以回查到原始评论；
- 权限角色不能看到未授权数据；
- 告警重复触发有去重和关闭规则。

## 8. 明确不做什么

- 一期不做电商平台爬虫和外部账号登录；
- 一期不做自动赔付、自动下架和自动质量裁决；
- 一期不把关键词命中当成情感模型结果；
- 一期不以少量合成数据训练后宣称真实业务效果；
- 一期不同时维护 `sentiment-plus` 和 `product-sentiment-plus` 两个产品；后者只作为历史参考；
- 一期不提供没有独立评测、模型产物和回滚记录的 BERT 生产发布。
