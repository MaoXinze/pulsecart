# PulseCart 详细使用手册

## 1. 适用范围

本文用于在本地启动和演示 PulseCart 当前 P1 闭环。推荐演示路径是：登录 -> 初始化合成数据 -> 查看质量报告 -> 完成人工审核 -> 创建训练运行 -> 同步训练结果 -> 创建问题卡 -> 推进到关闭验证。

## 2. 服务和目录

| 服务 | 地址 | 用途 | 当前状态 |
| --- | --- | --- | --- |
| Vue 3 工作台 | `http://127.0.0.1:3100` | 页面操作 | 已构建并接入领域接口 |
| FastAPI 业务后端 | `http://127.0.0.1:8006/jeecg-boot` | 认证、业务编排和 MySQL | 已接入 PulseCart P1 |
| NLP 训练服务 | `http://127.0.0.1:8100` | 训练、评测和训练任务状态 | 已验证 TF-IDF 基线 |
| MySQL 8 | `127.0.0.1:3306` | 系统和领域数据 | 需要本机已启动 |
| Redis 7 | 按本机配置 | 后续异步任务和短状态 | P1 不是强依赖 |
| MinIO/S3 | 按部署配置 | 原始文件和模型产物 | 当前本地版本目录可演示 |

本项目与 `product-sentiment-plus` 的关系是同一项目的历史版本，不需要同时启动。

## 3. 环境要求

- Windows 10/11 或兼容开发环境；
- Python 3.12.x；
- Node.js 22 LTS；
- pnpm；
- Docker Desktop（用于 MySQL、Redis、Milvus、MinIO 等依赖时）；
- MySQL 8；
- 可选：Redis 7、MinIO。

当前数据导入模块只依赖 Python 标准库，但后端和 NLP 服务分别需要各自的依赖环境。不要把宿主机 Python 3.14 可以运行某个脚本，误认为整个项目依赖已经安装完整。

## 4. 数据库初始化

PulseCart 使用继承的 JeecgBoot 数据库，并新增 `pc_` 前缀业务表，不修改 `sys_*` 系统表。

首次初始化顺序：

1. 创建目标数据库；
2. 执行 `jeecg-fastapi/sql/jeecgboot-slim.sql`，建立系统表和基础账号；
3. 执行 `jeecg-fastapi/sql/pulsecart_domain.sql`，建立五张领域表；
4. 确认 `pc_dataset_import`、`pc_review`、`pc_review_task`、`pc_analysis_run`、`pc_issue` 存在；
5. 用 `admin / 123456` 登录验证认证链路。

DDL 使用 `CREATE TABLE IF NOT EXISTS`，适合首次演示和空环境初始化，不是完整迁移工具。以后修改表结构应新增版本化迁移脚本。

## 5. 启动顺序

### 5.1 启动 NLP 服务

进入 `sentiment-ai` 目录，使用项目规定的 Python 环境启动服务。目标地址为 `http://127.0.0.1:8100`。

启动后先检查健康接口或训练接口是否可访问。NLP 服务不可用时，业务后端仍可登录、导入和审核，但创建训练运行会明确返回依赖错误。

### 5.2 启动业务后端

进入 `jeecg-fastapi` 目录，按现有 README 的配置启动 `run.py`。后端地址应为 `http://127.0.0.1:8006/jeecg-boot`。

重点配置：

- MySQL 连接串；
- 登录签名密钥；
- `sentiment_ai_base_url=http://127.0.0.1:8100`；
- 上传文件大小限制；
- 本地运行目录。

不要把数据库密码、JWT 密钥或对象存储密钥写入 Git。

### 5.3 启动前端

进入 `jeecgboot-vue3` 目录，启动开发服务，使用 `http://127.0.0.1:3100` 访问。前端代理应指向后端的 `/jeecg-boot` 前缀。

## 6. 页面演示步骤

### 6.1 登录

打开前端地址，使用：

```text
用户名：admin
密码：123456
```

登录后进入“商品体验”或“体验问题闭环”页面。如果菜单未出现，检查系统菜单初始化脚本和账号权限，不要直接改前端路由绕过认证。

### 6.2 初始化演示数据

在工作台点击演示数据初始化。后端会读取：

```text
sentiment-ai/data/demo/sweep_robot/reviews.csv
sentiment-ai/data/demo/sweep_robot/review_tasks.jsonl
```

预期结果：

- 数据集版本：`ds-9b8a078d8df7010a`；
- 评论约 1,200 条；
- 审核任务约 300 条；
- 再次点击不会重复插入相同任务；
- 返回质量报告和 `reused` 标记。

### 6.3 查看数据质量

在数据集列表查看：文件名、版本、SHA-256、接收行数、有效行数、拒绝行数和拒绝原因。演示数据应全部或大部分通过校验；如导入人为构造错误 CSV，应能看到对应拒绝原因。

### 6.4 完成人工审核

进入审核队列，选择 `pending` 任务。阅读原始评论和系统预测后：

1. 选择情感：`positive`、`neutral` 或 `negative`；
2. 选择零个或多个受控属性；
3. 对有歧义的样本填写说明；
4. 保存为 `approved`；
5. 需要二次核验时保存为 `verified`；
6. 文本无效时保存为 `rejected`，并填写原因。

建议为了演示训练链路至少审核 15 条，三类各 5 条。当前已经验证过该最小流程，但这只是流程验证样本，不足以支撑模型发布。

### 6.5 创建训练/评测运行

创建运行时填写：

```json
{
  "dataset_version": "ds-9b8a078d8df7010a",
  "model_version": "tfidf-logreg-demo-v1",
  "source_kind": "human_reviewed"
}
```

后端会从 MySQL 读取审核结果，构造训练记录并提交给 NLP 服务。页面显示 `queued` 时，说明任务已提交，不代表训练已经完成。

`model_version` 是不可复用的训练产物标识，只能使用小写字母、数字和连字符，长度为 3-80；同一版本已经排队、运行或完成后，请创建新的版本号，不要覆盖历史运行。

### 6.6 同步训练状态

在训练运行列表点击同步。状态可能为：

```text
queued -> running -> succeeded
                    -> failed
```

当前最小演示结果为 12 条训练、3 条测试，Accuracy `0.333333`，Macro-F1 `0.222222`。它会被标记为 `evaluation_only`，这是正确的质量门槛行为，不应手工改成可发布。

### 6.7 创建和关闭问题卡

创建问题卡时填写数据集版本、标题、属性、严重度、描述和来源评论 ID。例如：

```json
{
  "dataset_version": "ds-9b8a078d8df7010a",
  "title": "导航避障体验问题",
  "aspect": "导航避障",
  "severity": "high",
  "description": "多条已审核评论集中反映狭窄区域避障失败。",
  "source_review_ids": ["review-0001"]
}
```

状态操作必须按以下顺序：

```text
open -> in_progress -> pending_validation -> closed
```

处理人提交结果后，运营回查新评论并填写验证说明，才能关闭。关闭后的问题卡不可重新打开；发现问题未解决时，应从 `pending_validation` 返回 `in_progress`。

## 7. API 使用示例

API 前缀为：`http://127.0.0.1:8006/jeecg-boot/api/v1`。除登录外，接口均要求已有登录会话或 Bearer 认证信息。

| 用途 | 方法和路径 |
| --- | --- |
| 导入 CSV | `POST /datasets/imports` |
| 查看数据集 | `GET /datasets` |
| 初始化演示数据 | `POST /demo/bootstrap` |
| 查看审核任务 | `GET /review-tasks?status=pending&limit=50` |
| 保存审核 | `PATCH /review-tasks/{task_id}` |
| 创建训练运行 | `POST /analysis-runs` |
| 查看训练运行 | `GET /analysis-runs` |
| 同步训练状态 | `POST /analysis-runs/{run_id}/sync` |
| 创建问题卡 | `POST /issues` |
| 查询问题卡 | `GET /issues?status=open` |
| 更新问题卡 | `PATCH /issues/{issue_id}` |

审核请求示例：

```json
{
  "review_status": "approved",
  "reviewer_sentiment": "negative",
  "reviewer_aspects": ["导航避障"],
  "reviewer_note": "明确描述了狭窄区域避障失败。"
}
```

训练服务接口：

```text
POST http://127.0.0.1:8100/api/v1/training-runs
GET  http://127.0.0.1:8100/api/v1/training-runs/{job_id}
```

训练服务必须返回 `job_id` 和合法状态；业务后端不会接受无法识别的响应。

## 8. 本地数据位置

| 路径 | 内容 | 注意事项 |
| --- | --- | --- |
| `sentiment-ai/data/demo/sweep_robot` | 合成演示输入 | 可提交，不能代表真实业务数据 |
| `jeecg-fastapi/runtime/pulsecart/imports` | 版本化记录、报告、拒绝行 | 本地产物，按环境清理 |
| `jeecg-fastapi/runtime/pulsecart/raw` | 原始 CSV 快照 | 真实数据不得提交 Git |
| NLP 模型根目录 | 模型文件 | 建议放到独立持久化目录 |
| NLP 训练任务目录 | 任务和结果 | 失败任务保留用于诊断 |

## 9. 常见问题

### 登录失败

检查数据库是否初始化、账号是否存在、前端代理是否指向 `8006`，以及是否误用了另一个历史项目的接口地址。

### 初始化提示演示数据不存在

检查 `sentiment-ai/data/demo/sweep_robot/reviews.csv` 和 `review_tasks.jsonl` 是否存在。演示数据生成脚本可以重新生成，但不要把真实评论放入该目录。

### 训练提交失败

检查 NLP 服务 `8100` 是否启动、后端 `sentiment_ai_base_url` 是否一致、审核样本是否达到 15 条以及是否每条都有人工情感标签。

### 训练成功但不能发布

这是预期的门槛保护。检查 Macro-F1 和独立测试样本数。当前 15 条小样本只用于验证编排，不用于上线。

### 问题卡无法关闭

必须先从 `in_progress` 进入 `pending_validation`，并通过后端状态机提交关闭。前端显示按钮不代表后端允许跳转。

### Redis 或 MinIO 没有启动

P1 的导入、审核和训练编排可以在本地文件加 MySQL 路径下演示；异步任务、对象存储和大文件能力属于后续交付。文档和页面必须显示降级状态，不能伪造“已完成”。

## 10. 停止服务

在各服务所在终端使用对应的停止操作，按“前端 -> 后端 -> NLP 服务”的顺序停止本地进程。MySQL、Redis、Milvus 和 MinIO 属于共享依赖，除非确认只为本项目启动，否则不要随意停止容器。

## 11. 演示结束后的检查

- 页面能重新打开数据集和审核结果；
- 训练运行保留成功/失败状态和指标；
- 问题卡保留来源评论和关闭说明；
- 没有把 `.env`、密码、真实数据或模型权重提交到 Git；
- 简历数字均来自实际运行记录。
