# PulseCart 本地演示与简历说明

## 项目定位

PulseCart 是品牌或电商团队内部使用的商品体验问题管理平台。它不把情感分类结果当作自动决策，而是把评论导入、质量校验、人工审核、可追溯模型训练、问题卡处置和关闭验证串成可审计流程。

## 本地运行前提

- Python 3.12、Node.js 22 和 pnpm。
- MySQL 8 用于 JeecgBoot 用户、评论和问题卡数据；Redis 与 MinIO 用于后续异步任务和产物管理。
- 首次使用时执行 `jeecg-fastapi/sql/jeecgboot-slim.sql`，再执行 `jeecg-fastapi/sql/pulsecart_domain.sql`。
- 运营后端通过 `python run.py` 启动在 `http://127.0.0.1:8006/jeecg-boot`；Vue 工作台的开发代理已指向该端口。NLP 服务使用 `http://127.0.0.1:8100`。

当前主机尚未完成 Docker、MySQL、Redis、MinIO 的联合验收，因此需要按 `部署与初始化.md` 先接通本地依赖。测试脚本使用 SQLite 内存库，只验证领域规则，不替代真实 MySQL 验收。

## 推荐演示顺序

1. 用 `admin / 123456` 登录，进入“商品体验 -> 体验问题闭环”，初始化扫地机器人合成演示数据。
2. 展示数据集版本、质量摘要和 300 条待审核任务；完成不少于 15 条人工审核，并保留审核说明。
3. 创建训练/评测运行，展示模型版本、输入数据指纹、随机种子、混淆矩阵和模型 SHA-256。
4. 以明确的 `model_version` 批量预测，人工确认后创建“导航避障”或“回充失败”等问题卡。
5. 将问题卡从“待处理”推进到“处理中”“待验证”“已关闭”，关闭时填写验证说明并回查来源评论。

## 数据与模型边界

- 仓库中的 1,200 条扫地机器人评论和参考标签均为合成演示数据，不含真实消费者信息。
- P1 基线是只使用 `approved` / `verified` 人工标签的 TF-IDF + Logistic Regression 三分类模型；`synthetic_reference` 标签被代码拒绝进入训练集。
- 历史 BERT/RoBERTa 微调、压缩和模型 API 资产保留为 P2 对比实验，不应在没有独立评测记录时声称已经上线或优于基线。
- 简历或演示中只能引用实际运行产出的指标，不应声称真实电商泛化准确率、线上并发量或生产 SLA。

## 简历表述

> PulseCart｜商品体验问题管理平台｜个人开发
